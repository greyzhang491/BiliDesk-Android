# sync：可选加密跨设备同步

本模块提供默认关闭的坚果云WebDAV同步。账号、应用密码、恢复密钥与真实云端记录仅在用户设备配置，不得作为源码、测试常量、日志或发行附件上传。

| 文件 | 职责 |
| --- | --- |
| [SyncModel.kt](SyncModel.kt) | 纯数据模型、混合逻辑修订、逐歌单/歌曲合并、删除标记、每设备队列快照、视频进度及白名单编码 |
| [SyncCrypto.kt](SyncCrypto.kt) | 随机256位恢复密钥、AES-GCM认证加密、gzip压缩与解压边界 |
| [SyncSecrets.kt](SyncSecrets.kt) | 独立Android Keystore授权存储，凭据的字符串表示始终隐藏内容 |
| [WebDavSync.kt](WebDavSync.kt) | 固定HTTPS服务、无Cookie/无跳转客户端、严格目录解析、每设备独立文件 |
| [AutoSyncPolicy.kt](AutoSyncPolicy.kt) | 操作触发、事件合并、20分钟兜底与上传意图门控 |
| [SyncUploadWorker.kt](SyncUploadWorker.kt) | 仅联网补传已请求的上传，不携带凭据或同步内容作为任务参数 |
| [MusicSync.kt](MusicSync.kt) | 本机镜像、播放器/歌单事务接入、同步时机、状态流与显式续播 |

界面入口见[MusicSyncScreen.kt](../ui/MusicSyncScreen.kt)，操作说明见[使用说明](../../../../../../../../docs/RELEASE-0.2.5.md)。

## 合并与隔离

不得把两台设备的完整SharedPreferences直接相互覆盖。歌单名称和每首歌曲有独立修订；删除保留标记，已有UUID的歌单删除后不自动复活。只有本机相对于上次投影的真实变化产生新修订，未看到的云端新增项不能被解释为本机删除。

队列、当前歌曲和分P、进度、“下一首”及随机待播列表构成一份原子快照。每台设备保留自己的最近快照，避免空闲设备的一份旧队列丢掉另一台设备的续播入口。读取远端快照不调用播放器，点击“接着听”才恢复。

`MusicLibrary.syncUpdate`及`Store.syncHistory`在各自存储锁内读取当前状态并生成投影，保存的基线必须与这个投影对应，不能事后重新读取可能已被其他协程修改的StateFlow。

## 网盘协议约束

真实坚果云探测确认：PUT的`If-None-Match: *`不会阻止覆盖，不能将其用作并发比较交换。同步目录为`BiliDeskSync/vault-<密钥摘要>/`，每个安装只写自己的`device-<随机ID>.bdks`。不同恢复密钥使用不同子目录；相同恢复密钥并行初始化只写相同的常量标记，不会替换另一份密钥的库。不要把这些路径改回全设备共享单文件。

最外层网盘同步文件夹的名称有长度限制，并不能通过同一WebDAV接口删除；测试必须在专用文件夹下创建临时子目录。不要删除或列出用户的其他目录。

目录响应必须按严格UTF-8解码后使用Reader解析，拒绝DTD和实体声明，并禁止外部实体解析。Android Harmony不支持部分SAX特性开关，不能只在桌面JVM验证这些开关便视为Android兼容。

## 验证与边界

JVM测试覆盖并发合并、删除、分P与队列身份、时钟回退、密钥/密文篡改、大小与XML边界和无条件PUT下的隔离；设备测试验证存储、授权界面保护及真实播放器续播。协议探测只放在本地`work`，通过一次性内存管道接收授权，不能把授权复制成测试常量。

同步默认关闭，不增加常驻后台服务。最多16台设备、每份512KB密文/8MB解压内容；超过限制应保留本机数据并报告失败。只使用元数据白名单，不把图片/CDN地址、缓存、字幕或B站会话加入同步数据。

## 上传与续播

普通进度保存仅标记本机变化；暂停、继续、切歌、进度跳转、离开播放、后台及队列／歌单修改才请求上传，连续播放20分钟兜底。上传意图与镜像加密持久化，Worker不能把普通dirty状态解释为高频上传。短时操作合并，有最小发送间隔；服务限流遵守退避。

自动提示只在音乐页空闲且存在未处理的新记录时展示；正在播放或已经接过的同一记录不重复提示。手动设备面板始终允许选择其他设备的最近快照。设备名称修订与播放修订独立，改名不能伪造新的播放时间。
