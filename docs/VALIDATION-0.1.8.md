## 中间失败与验证边界

保留了测试夹具括号错误、非主线程读取播放器、已删除旧提示文字断言等中间失败。API35的UIAutomator还曾缓存滚动前的界面树；测试查询刷新可访问性缓存。音乐回到根页时，旧完整播放器也有同名歌单按钮，测试现在等待新根导航出现后再查找，媒体断言保持。

短视频旋转／连续换片的中间回归曾失败。触摸诊断确认一轮“普通滑动”的首次移动被注入器延迟至633ms，实际触发了长按与4倍锁速；更短的系统滑动也曾只送达按下和松开。测试现由系统生成320～400ms完整轨迹，长按场景继续使用明确的按住动作。应用同时把亮度／音量系统查询延后到确认垂直手势后，音量最大值在该次手势内复用，避免每次按下或移动都访问系统服务。

播放夹具按独立应用进程分次检查，原失败不计为成功，也不据此声称已确定所有物理设备上的根因。最终统计只引用完成的对应场景；重复运行不增加独立场景数。

测试设备为隔离的API35模拟器：手机1080×1920 / 420dpi，平板1600×2560 / 320dpi并实际旋转。没有红米K60／小米平板6物理设备的新增验收；未进行本轮真实B站播放、评论、字幕或CDN下载联调。平台权限、会员、地域、验证码与服务端限制仍然生效。

音频省流使用分离AAC／AVC样片和实际读取URI验证媒体源选择，不测量运营商计费流量；最低／均衡／高音质选择另由可用码率策略测试覆盖，不能保证每个真实视频提供多种音轨。音乐歌词只使用平台可读取的字幕，不自动生成。

最终通过数、源文件摘要和安装包关联以[验证摘要](../validation/interaction-checks-0.1.8.json)与[源码清单](../validation/source-integrity-0.1.8.json)为准。未使用额度重置券。
