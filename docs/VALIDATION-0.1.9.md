## 本轮范围

只调整音乐入口的紧凑竖屏布局、收起时返回上个根板块、通知显示和对应导航回归。平板音乐入口与已有完整播放器共用原来的组件。

114项JVM测试通过，无失败或跳过；Lint 0错误／36警告。手机3项、平板3项独立场景在同一最终主APK上全部通过。APK版本0.1.9 / code10，SHA256 `e981fac39280e788b54ba98ad40dfa848c4bb7a07284c27400c11adc45b5725d`，与0.1.8相同升级证书，16KB文件对齐验证通过。

## 实际检查方式

`MusicNavigationDeviceTest`实际点击分区与音乐入口，在手机竖屏检查四个其他主导航标签全部消失、返回箭头可用；搜索与歌单往返后仍保持沉浸。旋转横屏后检查导航可见，回到竖屏再次隐藏；实际点击收起和系统返回，核对回到分区，再从「我的」进入音乐验证返回目标更新。

播放使用真实Media3音频解码，检查导航过程中媒体项身份保持、音频继续输出、小播放条可见；另核对完整播放器内通知可以显示。平板同一场景保留竖屏主导航，实际旋转后检查左歌单／右播放器的相对位置。

`MusicModeDeviceTest`继续检查歌词跳转、搜索下一首、后台输出、真实系统媒体会话下一首、无字幕视频画面及媒体项身份；回到手机音乐根页的等待条件更新为完整播放器。`SocialMusicDeviceTest`的音频与外观场景继续实际切换三种样式、检查底部三个按钮的居中／等距／基线、显式画面与后台返回纯音频及设置保存。

每个场景以独立instrumentation进程运行，最终安装APK及实际测试APK摘要分别记录，不把旧版本或重复运行算作新通过。JVM和Lint结果来自本轮构建。

## 边界

使用隔离API35模拟器、假账号、本地拦截响应与独立音视频样片，无真实平台写操作或扣币。未新增真实B站网络联调，也没有红米K60／小米平板6的物理设备测试；本轮不重计0.1.8的全部互动与缓存场景。未使用额度重置券。

通过数和源码一致性以[验证摘要](../validation/interaction-checks-0.1.9.json)与[源码清单](../validation/source-integrity-0.1.9.json)为准。
