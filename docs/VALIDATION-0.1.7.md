# 0.1.7 登录恢复验证

## 旧版复现

在原签名0.1.6 APK上，以本地模拟账号先完成一次账号校验，再模拟断网、重建加密会话对象和 ViewModel。Cookie 仍存在，但 `user` 为空，账号入口错误地要求登录。该回归在旧版确实失败，原始日志仅保存在本地测试环境，不随源码公开。

## 修复路径

`AccountSession` 区分待校验、已验证、暂时不可同步、明确过期和本机存储暂不可读；`SecureCookies` 绑定并加密保存上次验证的账号资料。`MainActivity` 在前台监听默认网络事件并触发有限的账号校验，离开前台即解除监听。

网络异常、HTTP限制或格式错误不被当作“用户已退出”。导航接口明确返回未登录/过期才改变授权入口状态；缓存资料只用于显示和恢复体验，不授予平台访问权限。

最终测试数量、APK校验值及设备场景结果记录在 [验证摘要](../validation/interaction-checks-0.1.7.json)，运行源文件清单见 [源码清单](../validation/source-integrity-0.1.7.json)。

## 新增回归

最终 APK SHA256：`630e3ea03921170fcb1003320349857a89dc33a60729b1aba105fefd615d36aa`。本地95项JVM测试全部通过，Lint 0错误/33警告。同一APK在手机9项、横屏平板8项独立场景通过；跨进程场景分别执行seed/restore两阶段，每个设备计为一个场景。手机和平板实际安装文件的哈希均与最终APK一致。

- JVM：离线启动保留资料、重连恢复、无资料的旧版 Cookie 迁移、网络/HTTP/验证码/格式异常、明确过期、新账号、并发合并、重连替换阻塞请求、前台限流、退出后的迟到响应、旧账号迟到拒绝、本机读取/写入失败，以及导航返回解析。
- Android：相同的旧版失败场景、加密持久化/暂时读取失败保护、退出后拒绝旧 Cookie、分两次进程运行检查持久化，以及真实系统 Wi-Fi 开关触发可见账号自动恢复。
- 原有 `SmokeTest` 检查应用启动与 Cookie 加密/第三方域名隔离。相关播放、音乐或互动回归按摘要列出的实际场景记录。

另保留第一轮候选版的跨进程失败：使用异步偏好写入时，准备阶段在内存中成功，但进程结束后文件仍为空。最终版本在 I/O 线程确认关键会话与资料写入后再报告完成，并重新通过上述全部相关设备场景。原签名与0.1.6一致，APK 16KB文件对齐检查通过；源码清单记录92个运行/构建/测试源文件，原始失败及重测日志不随公开源码分发。

## 边界

测试使用模拟账号、拦截的 HTTP 返回和项目专用 Android 模拟器。系统 Wi-Fi 事件与进程重启是真实操作，但账号返回仍是模拟数据；没有真实账号会话验证或账号写操作，也未完成红米K60/小米平板6物理设备新增验收。视频和字幕等平台网络能力沿用此前记录的验证边界。
