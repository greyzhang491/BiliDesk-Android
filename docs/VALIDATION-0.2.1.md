`CommentsDeviceTest`通过真实Compose页面、UIAutomator触摸和Media3解码，检查头像、正文、元数据、浅深主题、赞踩请求、回复目标与CSRF、用户资料与投稿跳转、UID提及和昵称查找、原图查看、自动分页、返回位置保持、短视频评论与横竖屏连续播放，以及失败停止重试／结果未知保留草稿且不重复写入。

相关既有场景继续验证评论排序／点赞／楼中楼和创建收藏夹，普通全屏及短视频长按加速／恢复／拖动与倍率选择。长按时同时检查画面没有临时倍速文字框。

设备场景按独立进程运行并绑定主APK和测试APK的SHA256；只统计最终主APK上的成功场景，失败日志另行保留。界面预览使用独立绘制的头像和配图，标记UI DEMO，所有账号资料都是离线模拟数据。

## 实测边界

初期设备测试发现：空列表加载项与有内容时的底部项使用同一个稳定key，追加内容后LazyColumn可能继续锚定原加载项，导致首屏跳到后面的评论。现让底部项标识包含评论数量，既保留正常评论的稳定ID，也避免把旧加载项当作阅读位置。初次失败保留，不计为最终通过。

新增公开名片测试也覆盖了following布尔值与attention数量混用的情况，数量解析只接受数值字段。

点踩操作后，图标和可访问标签须跟随当前状态重新建立，与点赞按钮保持同样的状态标识，避免请求成功后仍呈现旧按钮。设备场景同时核对实际写入参数、读取结果和界面标签，再验证取消操作。

返回位置检查先主动滚离顶部，记录回复入口坐标，再进入线程、发表指定回复、返回并比对同一入口坐标。发表回复只刷新所属线程，不清除主列表或其他线程的位置和已确认互动；提交期间已返回上级，也按提交时的root标识更新对应线程。主动刷新仍可以重建当前评论分页。

初版测试把正文里的提及当作独立TextView查询，实际Compose链接以内联span呈现。现读取系统可访问树返回的文字字符坐标后注入真实点击，再验证对应主页与投稿；不以文字变色代替跳转验证。初期测试驱动失败记录保留并排除于通过数。

测试使用隔离API35手机／平板模拟器、本地拦截响应和独立音视频样片；没有真实账号互动、发表评论或扣币。本轮未完成真实B站网络联调，也没有红米K60／小米平板6真机验收。头像、属地与UID缺失时的服务端行为仍以真实接口响应为准，不能把离线响应通过当作平台权限或可用性的保证。

主评论与楼中楼的位置在本次评论组件生命周期内保留；主动刷新、切换排序、切换视频或切换账号会重建对应分页。关闭软件后不承诺恢复评论滚动位置。
